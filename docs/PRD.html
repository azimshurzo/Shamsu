01Product Overview

Shamsu AI-POWERED

A locally hosted, AI-powered no-code API creation platform. Record a workflow once in your real, logged-in browser. Shamsu's AI analyzes your recording, compiles it into a deterministic, self-healing automation, and generates a typed REST endpoint — all running locally via Ollama.

Target Users

Developers, small businesses, automation engineers in Bangladesh and South Asia

Differentiator

AI-powered analysis and self-healing execution, fully local via Ollama. Zero cloud dependency. Your machine, your data, your AI.

Mission

Enable anyone to turn browser workflows into callable REST APIs without writing code.

02Core Architecture

The system has five layers, inspired by stepped.ai's proven architecture:

Recording Layer

Chrome extension captures DOM actions via event listeners. Records clicks, inputs, navigations, and extraction targets.

Healing Layer

Deterministic selector matching with ranked fallbacks. Escalates to AI only when selectors fail.

Review Layer

Users review recorded steps, mark variables/constants, name fields, and generate APIs.

Execution Layer

Playwright executes workflows with healing ladder (L0-L5). Zero LLM calls on happy path.

API Layer

Auto-generated REST endpoints from workflows. Callable via HTTP with structured JSON responses.

Admin Layer

User management, payment approval, subscription plans, system settings.

03The Healing Ladder

Deterministic first. AI only when the site changes. Every heal becomes a reviewed patch, so the workflow gets stronger with age.

LevelStrategyCostDescription
L0Primary selector$0Recorded CSS selector hits + element fingerprint check
L1Ranked fallbacks$0test-id, ARIA, text, CSS, XPath — tried in order
L2Structural matching$0Weighted similarity scoring after markup changes
L3One-call LLM pick (Ollama)$0Screenshot + intent sent to Ollama llava model. Element coordinates returned.
L4Scoped agent (Ollama)$0Ollama agent takes over one step with screenshot feedback loop.
L5Human gate—Parks and notifies for 2FA, captcha, etc.

04Feature Requirements

4.1 Browser Extension

MVP (Current)

  • CSS selector recording
  • Extraction mode (click-to-mark)
  • JWT login with backend
  • Recording persistence across navigation

v2 (Planned)

  • Ranked selector fallbacks (L1)
  • Structural matching (L2)
  • One-call LLM healing (L3)
  • Minimal UI (start/stop button)

4.2 AI Analysis Pipeline (Ollama — Local)

  • Powered by Ollama running locally on user's machine
  • Text model (llama3.2): Analyzes recorded event stream, generates human-readable step labels
  • Vision model (llava): Screenshot analysis for healing L3-L4
  • Pipeline: Recording received → AI analyzes steps → suggests variables/constants → names fields
  • One-time cost per workflow (analysis runs once, not per execution)
  • Fallback: If Ollama not running, system works with deterministic selectors only (L0-L2)

4.3 Workflow Review Page

  • Shows AI-interpreted steps with human-readable labels
  • Variable/constant toggle per step
  • Extraction target marking
  • Field naming with AI suggestions
  • Visual step flow diagram

4.4 API Generation & Management

  • Auto-generated REST endpoints from workflows
  • API dashboard with usage stats and execution history
  • JSON schema for inputs/outputs
  • API key management with role-based access

4.5 API Execution Engine

  • Playwright-based execution with healing ladder (L0-L5)
  • Healing L3: Screenshot → Ollama llava → element coordinates (local, $0)
  • Healing L4: Ollama agent with screenshot feedback loop (local, $0)
  • Graceful fallback: If Ollama unavailable, stops at L2 (deterministic only)
  • Handles popups, overlays, dynamic content
  • Structured JSON response extraction
  • Multi-page pagination support

4.6 Authentication & Authorization

  • JWT-based auth with httpOnly cookies (web dashboard)
  • JWT token in response body (extension cross-origin)
  • Role-based access (USER, ADMIN)
  • Extension stores token in chrome.storage.local
